## 1. 요구사항 분석 (이유)

### 1.1 문제 제기 — 왜 이 시스템이 필요한가

- **독거노인 증가**: 1인 가구 고령자가 빠르게 늘고 있으나, 보호자(자녀)는 직장·거리 문제로 일상을 상시 확인하기 어렵다.
- **돌봄 공백의 3대 영역**:
  1. **정서적 고립** — 하루 대화 상대가 없어 우울·인지 저하 위험 증가
  2. **복약 관리 실패** — 만성질환 약을 깜빡하거나 과·미복용
  3. **응급 상황 대응 지연** — 낙상·통증을 보호자가 늦게 인지
- **기존 돌봄 서비스의 한계**:
  - 방문 요양·전화 안부는 **간헐적**(주 1~2회)이라 일상 모니터링 불가
  - 웨어러블·센서 기반 솔루션은 노인이 **착용/조작을 거부**하는 경우가 많음
  - 일반 AI 스피커는 **호출·조작이 어렵고**, 보호자와 데이터가 연동되지 않음

### 1.2 핵심 요구사항

| 구분 | 요구사항 | 이유 |
|------|----------|------|
| **사용성** | 노인이 별도 조작 없이 사용 (음성 호출어 기반) | 디지털 소외 계층의 학습 부담 최소화 |
| **정서 케어** | 자연스러운 일상 대화 + 감정 상태 추적 | 고립감 완화 및 정서 변화 조기 감지 |
| **복약 관리** | 자동 알림 + 음성 복용 확인 + 이력 기록 | 만성질환 관리의 핵심, 미복용 시 보호자 통지 |
| **보호자 연동** | 실시간 상태 동기화 + 푸시 알림 | 떨어져 사는 자녀가 안심하고 모니터링 |
| **응급 대응** | 위급 발화("아파", "쓰러졌어") 감지 → 즉시 알림 | 골든타임 확보 |
| **친숙한 폼팩터** | TV 옆 액자(태블릿) 형태로 거실에 상시 설치 | 노인 생활공간에 자연스럽게 융화 |
| **다대다 연동** | 1개 기기 ↔ 여러 보호자 / 여러 기기 관리 | 형제·가족 공동 돌봄, 시설 다중 입소자 대응 |

### 1.3 대상 사용자 (페르소나)

- **1차 사용자(시니어)**: 70~80대 독거노인, 스마트기기 조작에 미숙, 거실 TV 옆 액자 사용
- **2차 사용자(보호자)**: 30~50대 자녀, 스마트폰으로 부모 상태를 원격 확인
- **설계 결정**: 시니어 측은 **"조작 0" 음성 우선**, AI 페르소나는 **7살 손주**로 설정해 친근감·돌봄 동기 부여

## 2. 관련 기존 사항 (관련 연구)

### 2.1 유사 서비스 비교

| 서비스 유형 | 대표 사례 | 한계 | 본 프로젝트 차별점 |
|-------------|-----------|------|--------------------|
| AI 스피커 | 누구 케어콜, SKT AI 돌봄 | 화면 없음, 보호자 데이터 연동 약함 | 액자 화면 + 보호자앱 실시간 연동 |
| 응급안전 안심서비스 | 정부 보급 응급벨/센서 | 응급에만 초점, 정서·복약 미흡 | 정서 대화 + 복약 + 응급 통합 |
| 실버케어 로봇 | 효돌, 다솜이 | 고가, 보급·유지보수 부담 | 범용 태블릿 + 클라우드로 저비용 |
| 영상통화 액자 | 일반 디지털 액자 | 단방향 사진 표시뿐 | 양방향 음성 + AI 대화 + 모니터링 |

### 2.2 활용 핵심 기술 (선행 기술)

- **음성 인식(STT)**: OpenAI Whisper — 노인 발화·사투리에 강건한 범용 음성 인식
- **대화 생성(LLM)**: GPT-4o-mini — 페르소나 기반 자연스러운 일상 대화 및 감정 요약
- **음성 합성(TTS)**: OpenAI TTS (voice=nova) — 친근한 손주 음색
- **음성 활동 감지(VAD)**: Silero VAD (`@ricky0123/vad-web`) — 브라우저에서 발화 시작/끝 자동 감지, 버튼 조작 불필요
- **비전 인식**: Google MediaPipe (Tasks Vision) — 손 제스처(가위바위보), 신체 포즈(스트레칭)를 브라우저에서 직접 처리
- **실시간 데이터 동기화**: Firebase Firestore — 시니어 앱과 보호자 앱 간 무서버 실시간 연동
- **실시간 영상**: LiveKit (WebRTC) — 보호자 요청 시 온디맨드 원격 카메라 모니터링
- **푸시 알림**: Firebase Cloud Messaging(FCM) — 복약/응급/세션 종료 통지

### 2.3 기술 선택의 근거

- **클라우드 중심 재설계**: 초기 라즈베리파이(RPi5) 에지 서버 계획을 폐기하고, **범용 태블릿(갤럭시 탭 S5e) 웹 클라이언트 + 클라우드 서버** 구조로 전환. 이유 — 하드웨어 보급·유지보수 비용 절감, 무선 업데이트(웹) 용이, 멀티기기 확장성.
- **브라우저 우선(Web-first)**: 비전·VAD를 클라이언트(브라우저)에서 실행해 서버 부하·지연을 줄이고, 별도 앱 설치 없이 URL 접속만으로 동작.
- **Firestore 채택**: 보호자 앱(React Native)과 시니어 앱(웹/FastAPI)이 **공통 실시간 DB**를 공유하도록 해, 서버 간 직접 통신 없이 느슨하게 결합(loose coupling).

## 3. 설계 (화면 · DB)

### 3.1 시스템 아키텍처 (3계층)

```
┌──────────────────────────┐     ┌──────────────────────────┐     ┌──────────────────────────┐
│  ① 시니어 기기 계층        │     │  ② 클라우드 서버 계층       │     │  ③ 보호자 앱 계층          │
│  (갤럭시 탭 웹 클라이언트)  │     │  (FastAPI / Render)        │     │  (React Native)            │
│                          │     │                          │     │                          │
│ • 디지털 액자 화면         │◀───▶│ • WebSocket 상태/음성 허브  │     │ • 페어링·모니터링 대시보드  │
│ • 카메라/마이크/스피커     │ WS  │ • Whisper STT / GPT / TTS  │     │ • 복약 등록/캘린더          │
│ • MediaPipe 비전(게임)     │     │ • 감정 분석·복약 스케줄러    │     │ • 사진/음성 메시지 전송     │
│ • Silero VAD(음성감지)     │     │ • LiveKit 영상 퍼블리셔     │     │ • 푸시 알림 수신(FCM)       │
└──────────────────────────┘     └────────────┬─────────────┘     └────────────┬─────────────┘
                                              │                                │
                                              ▼                                ▼
                                  ┌───────────────────────────────────────────────────┐
                                  │      Firebase (Firestore 실시간 DB + FCM 푸시)       │
                                  │  devices · sessions · medications · photos · ...    │
                                  └───────────────────────────────────────────────────┘
```

- **역할 분담**: 김승진 = 시니어 측(`frontend/` + `backend/`), 손윤호 = 보호자 앱(`ai-bum-app`)
- **접점**: Firestore(실시간 동기화), LiveKit(영상), FCM(푸시 알림) 규약
- **동시성**: 시니어 기기 1대 = 음성 세션 1개. 보호자-시니어는 **다대다(N:M)** 관계

### 3.2 화면 설계 (시니어 태블릿)

상태 머신: `idle(액자)` → `greeting(인사 5초)` → `active(대화/콘텐츠)` → (무응답 시 복귀)

| # | 화면 | 표시 조건 | 구성 요소 |
|---|------|-----------|-----------|
| 1 | **IdleScreen** (디지털 액자) | 미페어링 또는 평상시 | 시계, 날씨, (미페어링 시) 6자리 페어링 코드 |
| 2 | **GreetScreen** (인사) | 얼굴 감지 시 5초 | "안녕하세요!" 환영 애니메이션 |
| 3 | **ActiveScreen** (콘텐츠) | 대화 모드 | 보호자 업로드 사진 슬라이드쇼 |
| 4 | **ReminderScreen** (알림) | 복약/일정 시각 도달 | 약 이름·시간, 15초 카운트다운 |
| 5 | **CognitiveGame** (게임) | "게임하자" 발화 | 가위바위보 져주기(손 제스처 인식) |
| 6 | **StretchingGuide** (운동) | "운동하자" 발화 | 신체 포즈 인식 스트레칭 가이드 |
| 7 | **SubtitleBar** (자막) | 대화 중 상시 | AI 발화 자막, 마이크 리스닝 상태 |

화면 전환은 500ms 페이드(exit → enter) 애니메이션 적용.

### 3.3 화면 설계 (보호자 앱)

- **페어링 화면**: 시니어 액자의 6자리 코드 입력 → 연동
- **홈 대시보드**: 오늘 감정 상태, 최근 감지 시각, 주간 감정 추세 차트
- **복약 관리**: 약 등록/수정(이름·시간·용량·재고), 복약 캘린더(처방/복용/미복용)
- **모니터링**: LiveKit 원격 카메라 토글, 실시간 영상
- **소통**: 사진 업로드, 음성 메시지 전송
- **알림**: 복약 미복용·응급·세션 종료(감정 리포트) 푸시 수신

### 3.4 데이터베이스 설계 (Firebase Firestore)

> 컬렉션 11종. 시니어 앱(FastAPI)과 보호자 앱(RN)이 동일 Firestore를 공유하며, 각 컬렉션의 읽기/쓰기 주체를 규약으로 분리.

#### 컬렉션 명세

**`devices/{deviceId}`** — 기기 등록·상태(페어링의 중심)
```
deviceId          : string    기기 고유 ID (예: frame-senior-01)
pairedUids        : string[]  연동된 보호자 UID 목록 (1:N 다중 보호자)
family_id         : string    가족 그룹 식별자
paired            : boolean    페어링 완료 여부
pairing_code      : string?    6자리 코드(사용 후 폐기)
code_expires_at   : number     코드 만료 시각(epoch)
lastSeen          : Timestamp  하트비트(생존 신호)
currentStatus     : string     idle | greeting | active
lastPillTakenAt   : Timestamp  마지막 복약 확인 시각
cameraRequested   : boolean    보호자 카메라 모니터링 요청 토글
```

**`pairing_requests/{code}`** — 페어링 코드 검증
```
deviceId   : string     대상 기기
expiresAt  : Timestamp   만료(생성 5분 후)
claimed    : boolean     보호자가 코드 입력 완료 여부
claimedBy  : string?     입력한 보호자 UID
createdAt  : Timestamp
```

**`families/{family_id}`** — 가족 그룹·보호자 정보
```
device_id  : string
guardians  : [ { user_id, name, email, fcm_token } ]   보호자 배열
created_at : Timestamp
updated_at : Timestamp
```

**`sessions/{sessionId}`** — 대화 세션 + 감정 리포트
```
device_id      : string
messages       : string[]   대화 로그 ["사용자: ...", "AI: ..."]
emotion_report : string     "[기분 점수: 75/100]\n[감정: happiness]"
pill_taken     : boolean     세션 중 복약 확인 여부
is_emergency   : boolean     응급 발화 감지 여부
message_count  : number      메시지 교환 수
created_at     : Timestamp
```

**`medications/{deviceId}/items/{itemId}`** — 복약 스케줄(보호자 등록)
```
name       : string   약 이름 (예: 혈압약)
time       : string   복용 시각 "09:00"
dosage     : string   용량 (예: 1정)
notes      : string   비고 (예: 식후 30분)
stock      : number    남은 알약 수
enabled    : boolean   알림 활성화
created_at : string
```

**`medication_logs/{logId}`** — 복약 이력
```
device_id : string
med_id    : string
med_name  : string
slot      : string    예정 시각 "09:00"
taken_at  : string    실제 복용 시각(ISO)
date      : string    "2026-06-19"
source    : string    voice | manual
```

**`events/{eventId}`** — 일정(병원·가족 행사 등)
```
device_id   : string
date        : string   "2026-06-19"
time        : string   "15:00"
type        : string   family | medical | activity | other
title       : string
description : string
created_at  : Timestamp
```

**`photos/{photoId}`** — 보호자 업로드 사진
```
deviceId        : string
uri             : string    이미지 경로/URL
displayOnDevice : boolean    액자 표시 여부
uploaderName    : string
created_at      : Timestamp
```

**`detection_events/{eventId}`** — 세션 시작/종료 이벤트
```
device_id        : string
type             : string    session_start | session_end
duration_seconds : number     (session_end 시)
timestamp        : Timestamp
```

**`users/{userId}`** — 보호자 계정
```
email         : string
name          : string
password_hash : string   bcrypt
created_at    : Timestamp
```

**`photo_notifs/{notifId}`** — 새 사진 표시 알림 트리거
```
url       : string
deviceId  : string
timestamp : Timestamp
```

#### 읽기/쓰기 규약 (앱 간 데이터 계약)

| 컬렉션 | 시니어 앱(backend) | 보호자 앱(RN) |
|--------|--------------------|----------------|
| devices | 읽기(상태)·쓰기(lastSeen, currentStatus, lastPillTakenAt) | 쓰기(pairedUids, cameraRequested) |
| pairing_requests | 읽기(감시) | 쓰기(코드 입력) |
| families | 읽기 | 쓰기(보호자 정보) |
| medications | 읽기(스케줄) | 쓰기(약 CRUD) |
| sessions | 쓰기(세션 저장) | 읽기(대화/감정 분석) |
| medication_logs | 쓰기(복용 기록) | 읽기(캘린더) |
| photos | 읽기(슬라이드쇼) | 쓰기(업로드) |
| detection_events | 쓰기 | 읽기(활동 분석) |

## 4. 구현 (화면 위주)

### 4.1 시니어 액자 — 화면 흐름

#### (1) 디지털 액자 & 페어링 (IdleScreen)

- 평상시 거실 TV 옆에서 **시계 + 날씨**를 표시하는 액자로 동작.
- 미페어링 상태면 `POST /api/pairing/code`로 **6자리 코드**를 자동 발급해 화면에 표시(5분 유효, 만료 시 자동 재발급).
- 보호자 앱이 코드를 입력해 `POST /api/pairing/verify`가 성공하면, 서버가 WebSocket으로 페어링 완료를 통지 → 액자가 정상 운영 모드로 전환.

> **구현 화면 캡처 위치**: `[그림 4-1] 디지털 액자 + 페어링 코드 화면`

#### (2) 자동 인사 (GreetScreen)

- 태블릿 카메라 프레임이 `/ws/media/{device_id}`로 서버에 전송되고, 서버는 OpenCV DNN(res10 caffemodel)으로 **얼굴을 감지**.
- 얼굴 감지 시 상태가 `greeting`으로 바뀌며 "안녕하세요!" 인사를 5초간 표시 + 음성 인사 발화(캔드 mp3 `greet_home`).

> **구현 화면 캡처 위치**: `[그림 4-2] 자동 인사 화면`

#### (3) AI 음성 대화 (SubtitleBar + 음성 파이프라인)

호출어 **"앨범아"**로 대화를 시작하는 손주 페르소나 AI.

```
브라우저 마이크
   │ Silero VAD가 발화 시작/끝 자동 감지 (무음 1056ms 대기 후 종료)
   ▼ WebSocket binary (WAV 16kHz)
서버 /ws/voice → VoiceAgent(별도 스레드)
   ├─ Whisper STT → 텍스트
   ├─ 호출어 판별("앨범아" 등 변형 매칭)
   ├─ GPT-4o-mini로 답변 생성 (7살 손주 시스템 프롬프트)
   └─ OpenAI TTS(nova) → mp3
   ▼ WebSocket {type:'speak', url:'/tts/latest'}
브라우저 <audio> 재생 (half-duplex: 재생 중 VAD 정지)
```

- 화면 하단 **SubtitleBar**에 AI 발화 자막과 마이크 리스닝 상태를 실시간 표시.
- 에코 방지를 위해 **half-duplex**(재생 중 마이크 정지) 적용.

> **구현 화면 캡처 위치**: `[그림 4-3] 대화 중 자막 패널`

#### (4) 복약 알림 (ReminderScreen)

- 서버 스케줄러(APScheduler)가 **매 분** `medications/{deviceId}/items`의 복용 시각과 현재 시각(KST)을 비교.
- 일치 시 ① ReminderScreen에 약 정보 + 15초 카운트다운 표시, ② "약 드실 시간이에요" 음성 발화.
- 노인이 **"약 먹었어"**라고 답하면 긍정 패턴 매칭(`먹었/묵었/챙겼` AND NOT `안먹/못먹/깜빡`) → `medication_logs` 기록 + `devices.lastPillTakenAt` 갱신 → 보호자 앱에 즉시 반영.
- 10분 내 미확인 시 보호자에게 **미복용 푸시(FCM)** 전송.

> **구현 화면 캡처 위치**: `[그림 4-4] 복약 알림 화면`

#### (5) 인지 활동 — 게임 & 스트레칭 (CognitiveGame / StretchingGuide)

- **"게임하자"** → 가위바위보 져주기 게임. MediaPipe(브라우저)가 손 제스처를 인식.
- **"운동하자"** → 신체 포즈 인식 스트레칭 가이드.
- 활동 중에는 음성 에이전트를 일시정지(자원 충돌 방지), 종료 시 재개.

> **구현 화면 캡처 위치**: `[그림 4-5] 인지 게임 / 스트레칭 화면`

#### (6) 사진 슬라이드 & 응급 감지 (ActiveScreen)

- 보호자가 업로드한 사진을 `photos` 리스너로 감지해 액자에 표시(신규 사진 20초 강조 후 슬라이드쇼 편입).
- 대화 중 **"아파", "쓰러졌어", "119"** 등 위급 발화 감지 시 `is_emergency=True` → 보호자 즉시 알림.

> **구현 화면 캡처 위치**: `[그림 4-6] 사진 슬라이드 화면`

### 4.2 보호자 앱 — 화면 흐름

- **페어링 → 대시보드(감정/감지 요약) → 복약 캘린더 → 원격 모니터링 → 사진/음성 전송**의 흐름.
- 세션 종료 시 서버가 GPT로 생성한 **감정 리포트**(`[기분 점수]`, `[감정 분류]`)를 `sessions`에 저장 → 보호자 앱이 읽어 추세 차트로 시각화.

> **구현 화면 캡처 위치**: `[그림 4-7] 보호자 대시보드`, `[그림 4-8] 복약 캘린더`, `[그림 4-9] 원격 모니터링`

## 5. 정리

### 5.1 결과 요약

- 독거노인의 **정서·복약·응급** 돌봄 공백을 하나의 **AI 액자**로 통합하고, 보호자 앱과 **실시간 연동**되는 3계층 시스템을 구현했다.
- 노인은 **조작 없이 음성("앨범아")만으로** AI 손주와 대화하고, 약을 챙기고, 게임·스트레칭을 한다.
- 모든 활동(대화·감정·복약·이벤트)은 **Firestore**에 기록되어 보호자가 원격으로 안심하고 모니터링한다.
- 초기 라즈베리파이 에지 구조를 **클라우드(Render) + 범용 태블릿 웹** 구조로 재설계해, 보급성·확장성(다대다 멀티기기)·유지보수성을 확보했다.

### 5.2 구현 완료 항목

- ✅ 브라우저 마이크/스피커 기반 클라우드 음성 파이프라인 (로컬 오디오 의존 제거)
- ✅ 호출어 → STT → GPT → TTS 대화 1바퀴 E2E (HTTPS 갤럭시탭 검증)
- ✅ 복약 자동 알림 + 음성 복용 확인 + 이력 기록
- ✅ 세션 감정 분석 리포트 + 보호자 연동
- ✅ 6자리 PIN 페어링 + 다중 보호자(N:M)
- ✅ MediaPipe 손/포즈 기반 게임·스트레칭
- ✅ LiveKit 온디맨드 원격 카메라
- ✅ Render Docker 배포(프론트+백엔드 단일 URL)

### 5.3 한계 및 향후 과제

| 과제 | 내용 |
|------|------|
| **응답 지연** | TTS(약 2.2s)가 최대 병목. OpenAI **Realtime API(speech-to-speech)** 전환이 근본 해법 |
| **상황별 캔드 음성** | 자주 쓰는 답변을 사전 녹음 mp3로 트리거해 TTS 지연 제거(부분 적용) |
| **보안 강화** | 노출된 키 교체(rotate), Firestore Security Rules 정교화 |
| **현장 실증** | 실제 노인 가정 장기 사용성·정확도 검증 필요 |
| **다국어/사투리** | 지역 방언 STT 정확도 추가 튜닝 |

### 5.4 기대 효과

- **노인**: 일상 대화 상대 확보로 정서적 고립 완화, 복약 순응도 향상
- **보호자**: 원격 실시간 안심 모니터링, 응급 골든타임 확보
- **사회적**: 저비용 범용 하드웨어 기반으로 돌봄 서비스 접근성 확대

## 부록 A. Firebase 설계도 생성용 프롬프트

> 아래 프롬프트를 **Claude 채팅(또는 그림 생성)에 그대로 붙여넣으면** Firestore 데이터 구조 다이어그램을 그려준다. ERD 형태와 컬렉션 트리 형태 두 버전을 준비했다.

### A-1. ERD / 관계도 생성 프롬프트

```
다음은 "독거노인 돌봄 AI 시스템(Senior Smile)"의 Firebase Firestore 데이터베이스 설계입니다.
이 구조를 한눈에 보이는 ERD(개체-관계 다이어그램) 형태의 도식으로 그려주세요.
각 컬렉션을 박스로, 주요 필드를 박스 안에 나열하고, 컬렉션 간 참조 관계를 화살표로 연결해 주세요.
시니어 앱이 쓰는 컬렉션과 보호자 앱이 쓰는 컬렉션을 색으로 구분해 주세요.
Mermaid erDiagram 문법으로 출력해 주세요.

[컬렉션 목록과 관계]

1. devices/{deviceId} — 기기·페어링 중심
   필드: deviceId, pairedUids[](보호자 UID 목록), family_id, paired, pairing_code,
        code_expires_at, lastSeen, currentStatus, lastPillTakenAt, cameraRequested

2. pairing_requests/{code} — 페어링 코드 검증
   필드: deviceId, expiresAt, claimed, claimedBy, createdAt
   관계: deviceId → devices

3. families/{family_id} — 가족 그룹·보호자 정보
   필드: device_id, guardians[]{user_id,name,email,fcm_token}, created_at, updated_at
   관계: device_id → devices, guardians.user_id → users

4. users/{userId} — 보호자 계정
   필드: email, name, password_hash, created_at

5. sessions/{sessionId} — 대화 세션 + 감정 리포트
   필드: device_id, messages[], emotion_report, pill_taken, is_emergency,
        message_count, created_at
   관계: device_id → devices

6. medications/{deviceId}/items/{itemId} — 복약 스케줄(서브컬렉션)
   필드: name, time, dosage, notes, stock, enabled, created_at
   관계: 상위 문서 deviceId → devices

7. medication_logs/{logId} — 복약 이력
   필드: device_id, med_id, med_name, slot, taken_at, date, source
   관계: device_id → devices, med_id → medications items

8. events/{eventId} — 일정(병원/가족 행사)
   필드: device_id, date, time, type, title, description, created_at
   관계: device_id → devices

9. photos/{photoId} — 보호자 업로드 사진
   필드: deviceId, uri, displayOnDevice, uploaderName, created_at
   관계: deviceId → devices

10. detection_events/{eventId} — 세션 시작/종료
    필드: device_id, type(session_start|session_end), duration_seconds, timestamp
    관계: device_id → devices

11. photo_notifs/{notifId} — 새 사진 표시 트리거
    필드: url, deviceId, timestamp
    관계: deviceId → devices

[핵심 관계 규칙]
- devices가 모든 컬렉션의 허브(중심)이며, 대부분 device_id로 참조됨
- devices ↔ users 는 다대다(N:M): 한 기기에 여러 보호자(pairedUids), 한 보호자가 여러 기기
- families가 device_id와 guardians(users)를 연결하는 가족 그룹 역할
- 색 구분: [시니어 앱 쓰기] sessions, medication_logs, detection_events, photo_notifs / 
          [보호자 앱 쓰기] medications, photos, families, pairing_requests / 
          [양쪽 공유] devices, users, events
```

### A-2. 컬렉션 트리 구조도 생성 프롬프트 (대안)

```
위와 동일한 Senior Smile Firestore 설계를, 이번에는 "컬렉션 계층 트리" 형태로 그려주세요.
루트 컬렉션 → 문서(ID 패턴) → 주요 필드 → 서브컬렉션 순서로 들여쓰기 트리로 표현하고,
medications 아래 items 서브컬렉션처럼 중첩 구조가 드러나게 해 주세요.
Mermaid flowchart(또는 graph TD) 문법으로 출력해 주세요.
컬렉션 11종은 부록 A-1의 목록과 필드를 그대로 사용하세요.
```
